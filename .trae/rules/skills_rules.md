# Skills 使用规则

> 定义项目中 Skills 的使用规范和灵活策略。

## 🎯 核心原则

### 必要 vs 可选

- **必要 Skills** - 每个项目必须使用的核心 Skills（见下表）
- **可选 Skills** - 根据具体需求灵活选用，不是每个项目都必须

### 动态扩展

SOLO Coder 在需求分析阶段完成后，必须：
1. 分析项目需求，识别需要哪些额外 Skills
2. 制定详细的 Skills 使用计划
3. 记录在项目上下文中，作为执行指南

## 📊 决策流程

### 1. 项目启动时

```
检查所有可用 Skills
    ↓
识别必要 Skills（8 个）
    ↓
记录在项目上下文中
```

### 2. 需求分析完成后

```
分析需求文档
    ↓
识别技术领域（AI、移动端、数据库等）
    ↓
选择对应领域的可选 Skills
    ↓
更新项目上下文的 Skills 使用计划
```

### 3. 每个阶段开始时

```
查看项目上下文的 Skills 使用计划
    ↓
调用必要 Skill（必须）
    ↓
根据当前任务调用可选 Skills（按需）
    ↓
记录调用的 Skill 到阶段日志
```

## 💡 使用策略

### 何时调用可选 Skills？

- **技术栈涉及特定领域** → 调用对应领域 Skill
  - 例如：需要 PostgreSQL 高级特性 → `se-database`
  - 例如：需要集成 OpenAI API → `se-ai-integration`

- **遇到特定问题** → 调用问题解决类 Skill
  - 例如：性能瓶颈 → `se-performance`
  - 例如：安全漏洞 → `se-security`

- **需要专业指导** → 调用专业领域 Skill
  - 例如：UI 设计不明确 → `se-ui-design`
  - 例如：API 设计混乱 → `se-api-design`

### 何时不调用？

- **任务简单，核心 Skills 足够** → 不调用
- **领域不相关** → 不调用
- **时间紧迫，可后续补充** → 标记为待办，不阻塞

## 📝 记录要求

每次调用 Skill 后，必须在 `docs/context/skills_log.md` 中记录：

```markdown
## [日期时间] - [Skill 名称]

**阶段**: [当前阶段]
**触发原因**: [为什么调用这个 Skill]
**输入**: [调用前的状态/文档]
**输出**: [生成的文档/代码]
**效果评估**: [是否达到预期]
```

---

## 🔄 动态更新

项目进行中，如果发现新的需求或问题：

1. **重新评估可选 Skills** - 是否需要新的领域 Skill
2. **更新 Skills 使用计划** - 记录到项目上下文
3. **回溯调用** - 如果之前遗漏，及时补充
