# 需求分析示例

## 示例 1：校园学习平台

### 项目背景

```markdown
# 校园学习平台需求文档

## 1. 项目概述

### 1.1 项目背景
学校目前使用 Excel 管理学生学习数据，效率低下且容易出错。
需要一个线上系统来管理学生学习进度、成绩和作业提交。

### 1.2 项目目标
- 实现学生学习数据数字化管理
- 作业提交和批改效率提升 50%
- 支持至少 1000 名学生同时在线

### 1.3 范围边界
**包含**: 学生管理、作业管理、成绩管理
**不包含**: 在线考试、视频课程、论坛讨论
```

---

### 用户角色示例

```markdown
## 2. 用户角色

| 角色 | 描述 | 权限级别 |
|------|------|---------|
| 学生 | 在校学习者 | 查看自己的数据、提交作业 |
| 教师 | 课程授课者 | 管理课程、批改作业、录入成绩 |
| 管理员 | 系统管理者 | 用户管理、系统配置 |
```

---

### 功能需求示例

```markdown
### REQ-001: 学生登录

**描述**: 学生使用学号和密码登录系统

**用户故事**: 作为学生，我希望登录系统，以便访问我的学习数据

**验收标准**:
- [ ] 输入学号和密码可以登录
- [ ] 密码错误时显示友好提示
- [ ] 连续 5 次失败后锁定账户 30 分钟
- [ ] 登录成功后跳转到个人主页

**业务规则**:
- 学号格式：8 位数字
- 密码长度：8-20 位，必须包含字母和数字
- 登录会话有效期：2 小时

**优先级**: P0
```

---

### 非功能需求示例

```markdown
## 4. 非功能需求

### 4.1 性能要求
- 页面响应时间 < 2 秒
- 支持 1000 人同时在线
- 数据库查询 < 500ms

### 4.2 安全要求
- 使用 JWT 认证
- 密码加密存储 (bcrypt)
- HTTPS 传输
- 防止 SQL 注入和 XSS 攻击

### 4.3 可用性要求
- 系统可用性 99.5%
- 每天凌晨 3 点备份数据
- 支持故障恢复
```

## 示例 2：RAG 知识库系统

### 项目背景

```markdown
# RAG 知识库系统需求文档

## 1. 项目概述

### 1.1 项目背景
公司有大量文档（PDF、Word、Excel），员工查找信息困难。
需要基于 RAG 技术构建智能问答系统，让员工可以自然语言查询文档内容。

### 1.2 项目目标
- 支持上传 PDF、Word、Excel 文档
- 实现基于向量检索的智能问答
- 回答准确率 > 85%

### 1.3 范围边界
**包含**: 文档上传、向量检索、问答界面
**不包含**: 多轮对话、语音输入、移动端
```

---

### 核心功能示例

```markdown
### REQ-001: 文档上传与解析

**描述**: 用户上传文档，系统自动解析并存储

**用户故事**: 作为管理员，我希望上传文档，以便系统可以基于文档内容回答问题

**验收标准**:
- [ ] 支持 PDF、Word、Excel 格式
- [ ] 单文件大小限制 50MB
- [ ] 自动提取文本内容
- [ ] 自动分块并生成向量
- [ ] 上传进度实时显示

**业务规则**:
- 只有管理员可以上传文档
- 文档按类别组织
- 支持版本管理

**优先级**: P0
```

---

### 数据需求示例

```markdown
## 5. 数据需求

### 5.1 核心数据实体

| 实体 | 描述 | 主要属性 |
|------|------|---------|
| Document | 上传的文档 | id, title, category, file_path, created_at |
| Chunk | 文档分块 | id, document_id, content, vector, chunk_index |
| Query | 用户查询 | id, question, answer, user_id, created_at |

### 5.2 数据关系
- Document 1:N Chunk (一个文档有多个分块)
- User 1:N Query (一个用户有多个查询)
```

## 示例 3：电商后台管理系统

### 核心流程示例

```markdown
### REQ-003: 订单处理流程

**描述**: 从下单到发货的完整流程

**用户故事**: 作为运营人员，我希望处理订单，以便客户可以收到商品

**验收标准**:
- [ ] 可以查看所有订单列表
- [ ] 可以筛选订单状态
- [ ] 可以修改订单状态
- [ ] 状态变更有记录

**业务规则**:
- 订单状态流转：待支付 → 已支付 → 已发货 → 已完成
- 只有"已支付"订单可以发货
- "已完成"订单不可修改

**优先级**: P0
```
